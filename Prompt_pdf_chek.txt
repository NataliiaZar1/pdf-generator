Домашнее задание: Создаем PDF Generator

Ты — опытный Python-разработчик и наставник для начинающего программиста.

Создай простой, понятный и работающий Python-проект для генерации PDF-документов на основе CSV/JSON-данных и HTML-шаблонов.

Это учебный проект. Код должен быть понятным начинающему программисту, хорошо структурированным, без чрезмерно сложной архитектуры и лишних функций.

1. Основная задача

Программа должна:

1. Читать все доступные CSV и JSON-файлы из папки "data".
2. Читать все HTML-шаблоны из папки "templates".
3. Показывать пользователю список доступных файлов данных.
4. Позволять выбрать один файл данных через консольный "input()".
5. Показывать список HTML-шаблонов и позволять выбрать один шаблон.
6. Выводить список доступных счетов (invoice) из выбранного файла данных.
7. Позволять выбрать конкретный счёт по "invoice_id".
8. Подставлять данные выбранного счёта в HTML-шаблон.
9. Генерировать PDF с помощью библиотеки WeasyPrint.
10. Сохранять готовый PDF в папку "output".
11. Автоматически открывать созданный PDF в системной программе просмотра PDF.

2. Структура проекта

Создай следующую структуру:

pdf_generator/
│
├── main.py
├── requirements.txt
├── README.md
│
├── data/
│   ├── invoices.csv
│   └── invoices.json
│
├── templates/
│   ├── invoice.html
│   └── invoice_modern.html
│
└── output/

Все пути должны быть относительными к папке проекта, чтобы программа работала независимо от расположения проекта на компьютере.

Если необходимые папки отсутствуют, программа должна корректно сообщить об этом или создать необходимые папки, если это безопасно.

3. Работа с CSV

Используй стандартную библиотеку Python "csv" либо "pandas", если это действительно необходимо.

Программа должна находить все файлы с расширением ".csv" в папке "data" и корректно читать их.

4. Работа с JSON

Используй стандартную библиотеку Python "json".

Программа должна находить все файлы ".json" в папке "data".

Предусмотри понятную обработку ошибок, если JSON-файл повреждён или имеет неправильный формат.

5. Формат данных

Для учебного проекта используй единый пример структуры данных счёта:

- "invoice_id"
- "invoice_date"
- "customer_name"
- "customer_address"
- "items"
- "total"

В "items" содержится список товаров или услуг. Каждый элемент включает:

- "name"
- "quantity"
- "price"
- "subtotal"

Если реальные файлы данных отсутствуют, создай демонстрационные CSV и JSON с несколькими счетами.

CSV и JSON должны содержать сопоставимые данные, чтобы можно было проверить оба формата.

Если структура предоставленных файлов отличается от примера, сначала изучи их и адаптируй программу под реальные данные, не теряя исходные данные.

6. HTML-шаблоны

Используй HTML-шаблоны для оформления счетов.

Для подстановки данных используй простой и понятный механизм шаблонов, например Jinja2.

Создай минимум два шаблона с разным оформлением:

- "invoice.html" — классический, аккуратный шаблон;
- "invoice_modern.html" — более современный дизайн.

HTML должен содержать:

- номер счёта;
- дату;
- информацию о клиенте;
- таблицу товаров или услуг;
- количество;
- цену;
- сумму по каждой позиции;
- итоговую сумму.

7. Кириллица

PDF должен корректно отображать русский язык.

Используй шрифт DejaVu Sans или Roboto.

При необходимости подключи шрифт через CSS. Не допускай появления квадратов или пропущенных символов вместо русских букв.

8. Генерация PDF

Используй библиотеку WeasyPrint.

PDF должен быть аккуратно оформлен, иметь читаемые шрифты, таблицы и корректные отступы.

При генерации PDF:

- используй выбранный HTML-шаблон;
- передавай в шаблон данные конкретного счёта;
- формируй имя файла на основе "invoice_id";
- сохраняй файл в "output";
- не перезаписывай существующий PDF без предупреждения или безопасного решения.

9. Автоматическое открытие PDF

После успешной генерации автоматически открывай PDF в системной программе.

Поддержи:

- Windows — через системное открытие файла;
- macOS — через "open";
- при возможности Linux — через "xdg-open".

Используй подходящий механизм определения операционной системы.

	Если автоматическое открытие не удалось, программа должна сообщить полный путь к созданному PDF.

10. Консольное меню

Сделай аккуратный, понятный вывод в консоли.

Пример:

========================================
           PDF GENERATOR
========================================

Доступные файлы данных:

1. invoices.csv
2. invoices.json

Выберите файл данных:

После выбора файла:

Доступные шаблоны:

1. invoice.html
2. invoice_modern.html

Выберите шаблон:

Затем:

Доступные счета:

1. INV-001
2. INV-002
3. INV-003

Выберите invoice ID:

Пользователь должен выбирать варианты по номеру из списка.

Проверяй ввод пользователя. Если введено неправильное значение, выводи понятное сообщение и предлагай повторить выбор.

11. Обработка ошибок

Предусмотри понятную обработку следующих ситуаций:

- папка "data" отсутствует;
- нет CSV или JSON файлов;
- папка "templates" отсутствует;
- нет HTML-шаблонов;
- выбран неправильный номер меню;
- файл данных повреждён;
- в данных отсутствует "invoice_id";
- выбранный invoice ID не найден;
- ошибка при создании PDF;
- ошибка при открытии PDF;
- папка "output" отсутствует.

Ошибки должны выводиться понятным русским языком.

Не используй сложные конструкции, если можно решить задачу простым и понятным способом.

12. Требования к коду

Создай основной файл "main.py".

Раздели код на понятные функции, например:

- "find_data_files()"
- "find_templates()"
- "load_csv()"
- "load_json()"
- "show_menu()"
- "choose_file()"
- "choose_template()"
- "choose_invoice()"
- "generate_pdf()"
- "open_pdf()"
- "main()"

Названия функций можешь немного изменить, если это делает код понятнее.

Добавь комментарии на русском языке к важным участкам кода.

13. Зависимости

Создай "requirements.txt" со всеми необходимыми библиотеками.

Не добавляй библиотеки, которые не используются.
